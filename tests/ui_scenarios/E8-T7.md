# E8-T7 — 本地推論服務(`horos serve` 與 Lab 頁的 Serve 區塊)

`horos serve` 是獨立的輕量服務:只有 `POST /predict`、`GET /health`、`GET /model_card`,
不需要專案目錄與 UI,部署到 Jetson 就是跑這個指令。Lab 頁的 Serve 區塊透過專案 Web API
啟停它,並可直接從瀏覽器丟圖測試(E8-S7)。

## 啟動

```bash
horos ui ./demo_project          # 專案需有至少一個 completed 的訓練 run
# 瀏覽器開 http://localhost:5000/lab
```

命令列版本(部署機):

```bash
horos serve --run <run_id> --format onnx --port 8080        # 專案內、匯出過 ONNX
horos serve runs/<run_id>/exports/onnx --host 0.0.0.0        # 直接指 bundle 目錄
horos serve <run_id>_onnx.zip                                # 或匯出的 zip
horos serve --run <run_id> --format checkpoint               # 用訓練 checkpoint(需 ML stack)
horos serve --run <run_id> --format tensorrt                 # Jetson / CUDA 機上匯出的 engine
horos serve --run <run_id> --format tflite                   # TFLite(LiteRT,CPU)
horos serve runs/<run_id>/exports/tensorrt/inference_model.trt   # 裸 engine 檔(旁邊有 class_names.txt)
```

## 測試步驟

### A. 啟停(Lab 頁)

1. 「Model under test」選一個 completed run。「Serve」區的 Source 下拉列出
   ONNX bundle / TensorRT engine / TFLite model / PyTorch weights bundle / training checkpoint;
   沒匯出過的格式呈灰色並註明「not exported yet」;在 macOS 上 TensorRT engine 灰色並註明
   「not supported on this platform」(hover 顯示能力清單的原因)
2. 選 ONNX bundle(或 checkpoint),Port 保持 8080,按 Start。狀態列先顯示「Starting — loading the model…」,
   數秒後變成「Running — http://127.0.0.1:8080 · onnx <run_id> · pid N」,下方出現三行 curl 範例
3. 點 URL 開新分頁:`/health` 回 JSON(status、model、kind、device、classes、requests)
4. 再按一次 Start(把 port 改成同一個)會被拒絕:「A service is already running…」;
   Port 被占用時同樣明確報錯,不會靜默改 port
5. 按 Stop:狀態回到「Not running.」,`/health` 連不上

### B. 從瀏覽器測服務(E8-S7)

6. 服務執行中,在「Test it」選一張照片:區塊右側顯示「N detection(s) ≥ 0.5: forklift ×2, pallet ×1」;
   這個請求是直接打到服務本身(CORS 已開),不是專案 API
7. 命令列照 curl 範例:`/predict` 回 `{image, width, height, instances[{bbox, score, category_id, category_name}], threshold}`;
   加 `annotated=1` 回 JPEG 疊圖;`threshold` 超出 0–1、沒附檔案都回統一錯誤格式 400

### C. 來源與授權

8. `GET /model_card` 回 bundle 內的 model_card.json(授權、類別、輸入/輸出契約);
   checkpoint 來源也有最小 model card(授權取自 registry)
9. 在 Training 頁匯出 TensorRT 後,Source 選 TensorRT engine 按 Start:狀態列變成
   「Running — … · tensorrt <run_id> · pid N · TensorRT 10.x (cuda-python memory) on cuda」;
   `/health` 的 `runtime` 欄位寫明實際執行的 runtime 與裝置。TFLite 同理,顯示「LiteRT … on cpu」
10. 三種成品對同一張圖回傳一致的偵測(類別、框位置、分數在容差內);沒裝 tensorrt 套件時,
    Start 立刻被拒絕並提示 `horos install --tensorrt`(沒有子行程被啟動);在 macOS 上選 engine
    是灰的、API 直接回 unsupported platform。engine 只能在 CUDA 執行、TFLite 只在 CPU 執行,
    `--device` 要求做不到的裝置會明確報錯,不會靜默改裝置

## 預期結果

ONNX / TensorRT / TFLite 成品都不需要訓練框架就能提供相同契約的偵測結果(Jetson 跑自己建的 engine);
Lab 頁一鍵啟停、瀏覽器與 curl 都能打到同一個端點;授權與類別資訊跟著服務走。

## 已知限制

- TensorRT engine 只在建置它的 GPU 架構 + TensorRT 版本上能載入;搬到別台機器會得到「could not deserialize」而非結果
- TFLite 在此只以 CPU 執行(LiteRT);GPU delegate 未接
- 每個專案同時只跑一個服務;`horos ui` 關掉時子行程一併結束
- 服務一次處理一個請求(session 非可重入),適合本機與小流量測試,不是高併發部署
