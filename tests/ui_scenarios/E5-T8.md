# E5-T8 — 訓練監控 UI

## 啟動

```
horos ui <project>          # 專案需有 train 與 valid 兩個非空 split
瀏覽器開 http://localhost:5000/train
```

## 測試步驟

### A. 超參數推導與覆寫（E5-S1, E5-S2）

1. 進入 Training 頁。「Start a training run」面板應顯示：
   - Model 下拉選單只列出可訓練模型（RF-DETR 四個尺寸），旁邊有 Apache-2.0 授權徽章
   - 超參數表格：每一列是「名稱 / 值 / why this value」，理由為完整句子
     （例：`635 images: small datasets need more passes to converge`）
2. macOS 上應看到黃色提示 `Suitable for small-dataset pipeline validation only.`
   （由 /api/v1/capabilities 驅動，非前端硬編碼）
3. 修改 epochs 輸入框（例如改成 5）：
   - 輸入框邊框轉藍、理由變成 `user override`、旁邊出現 `auto ↺` 按鈕
   - 其他列的推導值不變（部分覆寫不影響其他推導）
4. 按 `auto ↺`：值回到推導值，理由恢復
5. 切換 Model（如 Nano → Medium）：resolution 與 batch_size 隨模型重新推導
6. 類別不均 >3:1 的資料集會顯示 ⚠ 提示（誠實聲明後端沒有取樣 knob）

### B. 開始訓練與即時監控（E5-S3）

7. 按「Start training」：
   - 下方出現「Training run」面板：RUNNING 狀態徽章、run id、進度條
   - phase 文字顯示 `epoch k/N`，進度條隨 epoch 前進
8. 第一個 validation epoch 結束後：
   - 折線圖出現 loss 曲線（train/loss、val/loss 等，多序列各自配色 + 圖例）
   - 非 loss 指標（mAP 等）以卡片顯示最新值
9. 展開「Hyperparameters used (with reasons)」：
   - 顯示這個 run 實際使用的每個超參數、值、理由；被覆寫的值帶 `override` 徽章

### C. 停止訓練（E5-S4）

10. 訓練中按紅色「Stop」→ 確認對話框 → 確定：
    - 狀態轉為 STOPPED（灰色徽章）
    - 已完成 epoch 的 checkpoint 保留在 `<project>/runs/<run_id>/checkpoints/`

### D. Run 歷史

11. 「Run history」面板列出所有 run（新的在上）：id、模型、狀態、時間、checkpoint 檔名
12. 點任一列可載回該 run 的完整事件與曲線（不輪詢已結束的 run）
13. 重新整理頁面：進行中的 run 自動重新接上並繼續輪詢；無進行中則載入最新一筆

### E. 錯誤路徑

14. 沒有 valid split 的專案按 Start：紅色錯誤訊息
    `Training needs a non-empty train and valid split ...`，不會產生 run
15. 已有 run 在跑時再按 Start：明確拒絕（one training at a time），原 run 不受影響

## 預期結果

不填任何超參數按一個按鈕即可開始訓練；每個推導值都看得到理由；
loss 曲線即時更新；中停保留最佳權重；歷史 run 可回看。

## 已知限制

- 指標僅在 validation epoch 結束時更新（rfdetr 逐 epoch 驗證），batch 級 loss 不串流
- OOM 自動退階（E5-T6b/T6）尚未實作：OOM 會顯示為 failed 並附錯誤訊息
- 續訓（E5-T5）尚無 UI 入口
