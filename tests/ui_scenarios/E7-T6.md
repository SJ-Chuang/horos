# E7-T6 — Experiments page (run comparison, comparability, notes and tags)

The Experiments page (bar-chart icon in the nav, `/experiments`) answers "which
training run was best, and why". It reads only `/api/v1/experiments/*` (R2).

## How to run

```bash
horos ui ./demo_project          # a project with at least two training runs
# open http://localhost:5000/experiments
```

To reproduce the exact fixture used for this scenario (three fake runs, one
tagged, one evaluated, then a dataset edit) run the helper the tests use:

```bash
python - << 'PY'
import sys; sys.path.insert(0, "tests")
from pathlib import Path
from helpers.experiments import project_with_runs, write_eval
from helpers.data import write_sample_coco_dir
project, (r1, r2, r4) = project_with_runs(Path("./e7_demo"))
write_eval(project, r2.run_id, map_50=0.81, map_5095=0.55)
print(project.root)
PY
horos ui ./e7_demo/proj
```

## Test steps

### A. Sortable run table (E7-S3, E7-S1)

1. Open `/experiments`. Every run of the project is listed, newest first, with
   model, state badge, created time, epochs, best epoch, one column per metric
   the runs actually recorded (`loss`, and `test mAP50` etc. once a run has
   been evaluated), tags, a **Data** badge and an **Export** / **Open** button.
   The table never scrolls horizontally: when the panel is too narrow it folds
   secondary columns one by one (best epoch, model — which moves under the run
   id — created, non-sorted metrics, epochs, data badge) until it fits, and
   unfolds them again as the window widens.
2. Click the `loss` column header: the table re-sorts ascending on loss and the
   header shows an arrow; the best row's sorted cell turns green. Click again
   to flip the direction. The **Sort** dropdown in the toolbar mirrors the
   header choice and only offers keys the runs really carry.
3. Choose **State: completed**, then type `baseline` in **Tag**: the table
   narrows to matching runs; clearing the filters brings everything back.

### B. Comparability warning (E7-S4)

4. **Data vs** defaults to *project data today*. With an untouched dataset every
   Data badge reads `same`. Now change one annotation on the Annotator page
   (move a box on a train image), come back and press **Refresh**: every run
   trained before the edit shows a yellow `train changed` badge; hovering it
   explains "Not directly comparable with the project's current data: train
   split(s) differ — metrics were measured on different data".
5. Switch **Data vs** to a specific run: badges are now judged against that
   run's dataset fingerprint, so runs trained on the same data as it read
   `same` again.

### C. Side by side (E7-S1)

6. Tick two or more runs (up to 8). The **Side by side** panel appears with
   three tables: Metrics, Hyperparameters (each value with the reason the
   system chose it), Dataset. Only rows that differ are shown, highlighted in
   yellow; tick **show identical rows too** to see everything.
7. The panel header states whether the selected runs trained on the same data
   as the first one ticked; if not, it says how many did not.
8. **Clear selection** hides the panel.

### D. Notes and tags (E7-S5)

9. Click a row (not the checkbox). The **Run** panel opens with the
   comparability sentence, a notes textarea, a comma-separated tags field and
   a fact sheet (model, state, epochs, device, classes, split sizes, dataset
   fingerprint prefix, scores, evaluations).
10. Type notes and `baseline, nano`, press **Save**: "saved" appears, the tag
    chips show in the table row, and reloading the page keeps both. The URL
    hash carries the run id, so the link can be shared or bookmarked.
11. Tags are de-duplicated case-insensitively; a tag containing a comma cannot
    be entered (the field splits on commas by design).

### E. Into the export flow (E7-S2)

12. Press **Export** on a completed run (or **Open in Training · export** in
    the run panel): the Training page opens with that run selected and its
    Export section visible; unfinished runs read **Open** instead.

## Expected result

A user can rank runs by any recorded metric, see at a glance which runs are
no longer comparable because the dataset changed since they trained, put two
to eight runs side by side with only the differences highlighted, annotate
runs with notes and tags, and jump from the winner straight into export.

## Known limitations

- Metrics columns are limited to what runs record; a project whose runs never
  reported mAP has no mAP column (the fake backend used in tests reports loss
  only).
- Runs recorded before E7-T2 get their fingerprint back-filled from the
  snapshot on first view; runs whose snapshot was deleted show a grey `?`
  badge and no comparability judgement.
- The page does not auto-refresh while training is running; press
  **Refresh** (or reload) to pick up new runs.
